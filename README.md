# 一局江湖

手机游玩：[打开一局江湖](https://lynch715.github.io/yiju-jianghu/)

扫码海报：[打开并保存分享海报](https://lynch715.github.io/yiju-jianghu/share/jianghu-poster-v1.jpg) · [独立游戏二维码](https://lynch715.github.io/yiju-jianghu/share/game-qr.png)

仓库：[Lynch715/yiju-jianghu](https://github.com/Lynch715/yiju-jianghu)

金庸武侠题材的本地静态卡牌游戏，v0.12.1。无需安装依赖，无账号、付费和远程服务。

## 运行

直接打开 `dist/一局江湖.html` 即可离线游玩。该交付文件已内联全部代码、样式和SVG，无外部依赖。

开发源码在本目录运行 `npm start`，打开 http://127.0.0.1:8871 。源码使用ES模块，须通过HTTP打开。

修改后运行 `npm run build`，同步生成三个内容一致的单文件发行入口：`dist/一局江湖.html`、`dist/index.html` 与带版本号的HTML。

## 内容

- 三章对应16种有独立立绘、招式和机制的小说人物与势力，含余沧海、丁春秋、欧阳锋三位首领。
- 新局三章四十五程，每章十五程、39个地点，路线分岔与汇合，含战斗、高手、首领、八种奇遇、行商、歇脚和遗藏。旧存档保留原十八程。
- 60 张武学牌、20 张通用牌，每张均有精进效果；30 件实际生效的奇物。
- 创建侠客：自定义1—12字姓名，选择男女各3款立绘，确认后领取开局机缘；外观不影响属性、牌组或随机奖励。旧存档可从菜单修改姓名与立绘。
- 以基础十张牌开局：5张太祖长拳、4张抱元守一、1张吐纳，搭配粗布药囊，先从4份随机机缘中领取1份通用开局奖励。胜利后从随机3张牌中选1张或跳过；通过奖励、商店、奇遇、精进和移除逐步构筑牌组。
- 永久精进、临时精进、选牌消耗、虚无、保留、格挡保留、反震、自损、重复结算、X费攻击。
- 自动存档、继续游戏、JSON导出导入、可搜索的全牌图鉴及奇物图鉴。
- “辅助出招一回合”使用相同规则，无额外资源，不代表最优策略。

## 验证

`npm test` 检查卡牌基础版/精进版、伤害与格挡数值、所有奇物、核心联动、存档恢复与完整流程。

`npm run simulate` 输出基础起手、领取通用开局机缘后，四种选牌测试策略各五个固定种子的完整对局结果；测试策略仅用于模拟玩家选牌，不影响游戏奖励或初始牌组。数值仍是首轮设计，不代表已完成长期平衡。

## 文件

- `data.js`：80张牌的数值与说明、30件奇物、虚无元数据及章节。
- `players.js`：6款男女立绘、姓名校验与外观元数据。
- `assets/players/`：6张玩家立绘原图与对应运行用图。
- `art/player-prompts.md` / `.json`：全部玩家立绘提示词，`art/player-gallery.html`为六款形象总览。
- `enemies.js`：16种敌人的立绘映射、招式、数值与各章遭遇池。
- `assets/enemies/`：16张原始透明立绘；`runtime/`为等比例缩小后的运行用图，原图不改写。
- `art/enemy-prompts.md` / `.json`：内置 imagegen 的完整提示词；`art/enemy-combat-design.md`为具体招式数值。
- `journey.js`：独立于战斗随机数的版本化路线图、邻接校验和行路存档。
- `map-art.js`：轻量矢量山水、河流与地图图标，无新增位图资源。
- `engine.js`：与DOM无关的战斗及流程状态机，所有测试使用同一引擎。
- `app.js` / `style.css`：响应式界面、交互、图鉴与存档。
- `tests/`：独立数值断言、组合规则与整局回归。

世界采用群侠共处的架空江湖；卡牌效果、数值、故事均为游戏改编。带†的名称是游戏拆招或据原著物品改编的名称。原创辅助奇物在图鉴中标明。同时提供GitHub Pages网页版与本地离线单文件。

## v0.4随机开局机缘

每局从5种赠礼中随机抽3种，再从3种带代价的奖励中抽1种，组成4选1。不设置流派、方向或后续掉落绑定。选项及随机结果在生成时固定，刷新和返回重选不会重抽。

| 机缘 | 效果 |
| --- | --- |
| 故人赠金 | +75银两 |
| 养元固本 | +7气血上限并回复7气血 |
| 临别点拨 | 自选精进1张初始牌 |
| 轻装上路 | 自选永久移除1张初始牌 |
| 偶得残篇 | 随机3张非基础牌中选1张 |
| 涉险寻珍 | 失去8气血，获得随机随身奇物 |
| 古匣藏珍 | 加入1张心魔，获得随机珍奇奇物 |
| 倾囊求艺 | 交出全部银两，获得随机绝学 |

开局选择及领取结果自动存档，每局仅领取一次。旧版已开始的地图或战斗不会额外补发奖励。

## v0.5小说群敌与立绘

- 普通敌人：青城弟子、嵩山门人、星宿弟子、血刀门人、白驼山门人、日月教高手。
- 精英：木高峰、田伯光、血刀老祖、鹤笔翁与鹿杖客双人战、成昆、金轮法王。
- 首领：余沧海（破绽接重击）、丁春秋（气滞、寒气、毒）、欧阳锋（蓄力、半血逆练）。
- 16张图由内置 imagegen 按各自提示词独立生成，透明背景；游戏内“群敌录”可查看所有立绘与招式。
- 中毒在敌方行动结束后失去等量气血，随后层数减1，格挡无法抵挡；寒气压制下回合真气，最多减少2点。
- 血刀吸血以实际伤及气血为前提；玄冥二老可为同伴提供格挡，击败鹤笔翁会解除鹿杖客合击加伤；欧阳锋半血时立即更新预告进入逆练阶段。
- 敌方格挡在整轮敌方行动前统一清空，保证二老护持不会被同伴行动清空。破绽会持续到对应的敌方攻击结算，预告也计入前一个敌人的破绽效果。
- 旧战斗按章节对应新人物，保留现有气血、牌组、随机数与本回合已显示的预告；后续行动使用新招式。旧开局与既有进度继续兼容。

原图更新后，在macOS运行 `npm run art:prepare` 制作运行用图，再 `npm run build` 内联全部22张玩家与敌人图片，产物仍为无外部依赖的离线单文件。直接修改代码无需重复处理美术。

## v0.6玩家姓名与男女立绘

- 新局先创建侠客：输入1—12字姓名，从男性/女性各3张独立立绘中选择一张，再进入原有随机开局机缘。
- 名字支持中文、英文、数字及可见标点，统一空格与全角字符；不允许隐藏控制字符或换行。名字按文本转义显示。
- 名字与已选立绘在填写过程中自动保存；刷新后“继续此局”可继续创建。
- 战斗使用对应的完整透明玩家立绘，并显示自定义姓名；胜负结算也保留同一形象和名字。
- 菜单或侧栏的“姓名与立绘”允许旧存档修改外观；保存后回到原地图、战斗或奖励界面，卡牌、奇物、气血、回合、随机数均保留。可以取消修改。
- 立绘不授予属性、武学、奇物或掉落倾向。男女同一初始牌组，姓名和外观选择不消耗局内随机数。
- 6张玩家立绘由内置 imagegen 独立生成，原图和完整提示词均保留，离线发行版内联所有图片。

## GitHub Pages 发布

Pages从 `main` 分支的 `/docs` 发布。网页版按需加载独立的立绘文件，先显示界面；离线单文件继续内联全部立绘。

```sh
npm test
npm run build
npm run build:pages
git add .
git commit -m "Update game"
git push origin main
```

`docs/` 是生成的部署目录，修改游戏请编辑根目录源文件后重新构建。`docs/release.json` 记录版本及29个页面、脚本、样式和图片文件的SHA-256，用于核对线上版本。

手机用Safari或Chrome打开游玩链接即可，也可以添加到主屏幕。存档保存在当前设备的浏览器中；电脑本地版进度可通过游戏菜单导出JSON，再在手机网页版导入。

## v0.6.1 手机体验调整

手机首页按屏幕高度排布，单敌人与首领战采用等高立绘、对称站位，双敌人单独适配。卡牌删除单字装饰，突出牌名和效果。出招加入卡牌飞出、人物前探、命中闪动、伤害与格挡飘字；开启系统减少动态效果时直接完成结算。动画期间锁定重复操作，结算结果先自动保存，旧存档可继续使用。

## v0.6.2 手机底部回合栏

战斗中的真气与结束回合按钮固定在手机屏幕底部，滚动查看敌人、手牌或战报时始终可用。底栏适配底部安全区域，页面预留空间避免遮住内容；选牌弹窗显示在底栏上方，战斗结束后底栏自动收起。

## v0.6.3 手机固定手牌区

战斗手牌与回合操作组成固定底部区域，手牌横向滑动，使用较小卡面；上方保留敌我立绘与招式。长效果可通过“完整说明”展开阅读。抽牌堆、弃牌堆、消耗区与辅助出招仍位于底部区域，弹窗优先显示，切换目标或关闭窗口会保留手牌横向位置。

## v0.6.4 折叠手牌与点选展开

手机手牌改为一屏容纳的折叠牌列，每张显示费用、牌名和类型。点牌只展开完整牌面，再按“出招”才结算；可直接点另一张切换，也可收起。不可用牌仍可查看原因。额外手牌选择沿用确认窗口，桌面端保留直接出牌操作。

## v0.6.5 围攻遭遇与抱元守一

普通战斗包含单人、双人、三人阵容，首段可遇双人，后续可遇三人。精英新增随从组合，三章首领分别带同势力门徒。人数增加时按章节调节敌人血量、伤害并错开起手招式，每个敌人仍独立选目标、行动、受伤和死亡。阵容为原创游戏关卡编排，不表示小说原著人物结盟。U01 更名为“抱元守一”，保持费用与格挡效果，旧牌组 ID 不变。

## v0.6.6 敌我分排与立绘尺寸

手机战场改为敌人在上、玩家在下的两排布局，玩家采用横向信息栏，保留底部折叠手牌与回合操作。精英、首领与玩家立绘等高，普通敌人立绘为其一半；每个敌人的招式、血量、状态和目标按钮仍独立显示。桌面保留左右战场，普通敌人立绘同样缩小。

## v0.6.7 武学与奇物外观、统一牌面与资源压缩

新增 13 张原创水墨武学主题插画，按招式内容匹配 80 张武学与通用牌及两张状态/诅咒牌，同类武学共享配图。奖励、商店、图鉴、牌组和桌面手牌显示小牌面，手机点开显示大牌面。普通完整牌面固定 160×240，展开固定 260×390，均为 2:3；长效果在文字区滚动，卡牌不会随内容变高。手机折叠牌条保持同屏等高、等宽，折叠时不加载插画。

22 张人物立绘改用高 480 像素、保留透明的 WebP，13 张卡图使用 480×320 WebP。全部运行图片从原先 8,497,854 字节降为约 1.32 MB（包含新增配图），减少约 84%。原始人物 PNG 保留；新增高清卡图仅在本地 `assets/cards/originals/`，GitHub 与 Pages 使用压缩版。构建会移除 Pages 输出中已不用的 PNG 副本。离线单文件约 1.96 MB。

尺寸规范见 `art/card-design.md`，内置 imagegen 的完整提示词见 `art/card-prompts.json`，逐类资源统计见 `art/runtime-budget.json`。`npm run art:prepare` 使用本机 `cwebp` 重新生成运行图片，不调用网络；已有压缩卡图的发布仓库可直接构建。

30 件奇物各有独立矢量物件外观，覆盖药囊、酒葫芦、护腕、石锁、护心镜、甲衣、剑刀、竹棒、指环、药匣、鼎、寒玉床、曲谱等，显示于奖励、商店、随身栏、图鉴和详情。图标由原生 SVG 绘制（`relic-art.js`），整套约 13 KB，无额外图片请求，离线构建同样完整包含。

## v0.7.0 四十五程与江湖行路图

新局扩展为三章各十五程，共四十五程。每章39个可选地点，按种子生成岔路与汇合；只能选择与上一步相连的下一站，不能跨路、重走旧站或越过首领。第八程为遗藏，可从两件随机奇物或65银两中选一份；第十四程可歇脚，第十五程挑战首领。普通敌人强度按章内进度平滑增长，既有战斗机制与卡牌规则不变。

地图以纵向山水卷轴呈现，加入河道、山势、地名与曲线小径，区分已走、当前、可达与未至地点。支持章节预览、滚动与定位当前行程；战斗中查看地图保持只读。新增药庐、旧匣、残碑悟武与渡口试手四种实际生效的奇遇，和原有四种共八种。地图使用原生 SVG 与 CSS，保持现有轻量美术资源。

存档版本升级为6；新路线只保存版本、已走节点和当前地点，刷新不重抽路线，也不消耗战斗/奖励随机数。v0.6.7及更早的旧局继续原十八程，已有气血、牌组、敌方招式与行程不改写；新开一局启用四十五程。数值与路线仍需持续游玩平衡，自动模拟结果仅证明流程可完整结束。
